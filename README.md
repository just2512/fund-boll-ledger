# 基金阶梯账本（Fund BOLL Ledger）

一款面向个人使用的场内基金计算与记账工具，使用 React + TypeScript 前端，通过 Tauri 原生窗口运行于 Windows，并构建为 Android APK。保留浏览器 PWA 作为可选预览；行情仅在用户点击刷新时读取东方财富公开报价，失败时依次尝试腾讯、百度股市通；不自动轮询、不连接券商、不自动下单。日/周/月历史 K 线同样三级回退：东方财富 → 腾讯（ifzq.gtimg.cn）→ 百度股市通（finance.pae.baidu.com）。百度现价缺少可信交易日期时只用于价格展示，不用于确认技术状态。

> Windows 使用独立桌面窗口启动，不需要先打开浏览器。Android 使用可安装 APK，不需要通过浏览器“添加到主屏幕”。每台设备分别保存本地账本；首版无云同步，跨设备需通过 JSON 备份迁移。

## 首版交付范围

- **基金档案**：手动维护基金名称、代码、市场、类别、最小价格变动单位；所有基金共用全局固定费用费率，不在单只基金上配置佣金。
- **五个价格基准**：BOLL 上轨、中轨、下轨、昨日收盘价、上一次成交价。另有独立的手动当前价格输入。
- **实时重算**：当前输入价会分别对比五个基准，并显示日/周/月 BOLL 区间位置：`(当前价 − 对应周期下轨) / (对应周期上轨 − 对应周期下轨)`，按百分比展示；可以低于 0% 或高于 100%。日 BOLL 仅在位置 ≥100% 时将数值显示红色、≤0% 时将数值显示绿色；50% 不触发颜色变化。周/月以 50% 为界，≥50% 整个模块红色、<50% 整个模块绿色。周/月轨道价不作为价格基准展示或编辑，仅用于计算位置。
- **点击刷新行情**：东方财富优先，失败依次回退腾讯、百度股市通获取最新价和昨收；百度报价缺少可信交易日期时不参与确认技术状态；日 BOLL 轨道保留为可编辑价格基准；周/月只获取计算区间位置所需的内部边界，不展示、不提供周/月轨道价格输入。日 BOLL 轨道四舍五入保留三位小数。
- **十档价格阶梯**：对选定基准生成向上和向下 1%—10% 阶梯；每一档相对原始基准独立计算，并按该基金配置的最小价格变动单位舍入。当前价会标注已越过、下一档、尚未到达或超出十档范围。
- **BOLL + MACD 技术状态**：顶部先显示按 BOLL 中轨方向、MACD DIF/DEA 排列与零轴位置硬条件生成的整体技术倾向（多周期偏多/偏空、短线回调/反弹、震荡、分歧或待确认），再简要列出日/周/月各自的“带宽＋中轨＋最新交叉”组合条件。该倾向不是买卖建议；不使用分数或权重。周期详情默认日线直接可见，切换周线/月线一次直达，不设双层折叠。详情展示指标计算依据、来源与元数据，并提供最近 20 根确认 K 线历史及分页。只使用已确认 K 线，不产生交易指令、不修改账本。MACD 状态发布门槛为日线 160 根、周线 160 根、月线 100 根确认 K 线。
- **交易明细**：逐笔记录日期时间、买/卖、价格、份额、佣金、经手/过户等费用、印花税、其他费用与备注；允许编辑、删除，并标记费用是否已对照东方财富实际成交明细核对。
- **持仓与盈亏**：加权平均成本法，买入费用纳入持仓成本；卖出费用计入已实现盈亏；展示当前持仓、成本、已实现盈亏、浮动盈亏与费用拆分。
- **价格历史**：主动保存当日输入的五个基准、当前价、报价单位和备注。
- **备份**：完整 JSON 导入/导出；交易明细 CSV 导出。
- **原生应用外壳**：Tauri 桌面窗口与 Android APK 共用同一套 React 界面和计算逻辑；PWA 仅作为可选网页预览。无账号、无云端数据传输。

## 原生应用构建

具体环境要求和设备验收步骤见 [原生应用与折叠屏验证说明](docs/NATIVE_APP_AND_DEVICE_TEST.md)。

Windows 运行 `scripts/build-windows.ps1` 生成独立窗口程序与安装包；Android 运行 `scripts/build-android.ps1` 生成面向 ARM64 的 APK。

## 本地运行

需要 Node.js 20 或更高版本。首次安装依赖需要网络访问 npm registry。

```bash
npm install
npm run test          # 单元测试（计算核心 + 边界）
npm run build         # tsc 类型检查 + Vite 生产构建
npm run dev           # 浏览器预览（可选）
npm run desktop:dev   # Windows 原生窗口开发模式
npm run desktop:build # 生成 Windows 桌面安装包
npm run android:init  # 首次初始化 Android 工程
npm run android:build # 构建 ARM64 Android APK
npx playwright test   # 端到端测试（使用系统 Edge，真实交互）
```

普通网页预览仍可使用 `npm run dev`，但日常启动请使用 Tauri 原生应用；Android 请构建并安装 APK。

## 本地原生应用开发依赖

需要 Node.js 20+、Rust stable、Tauri CLI 2.11.4。Windows 桌面还需要 Visual Studio C++ Build Tools 和 WebView2；Android 需要 Android Studio、JDK 21、SDK Platform 36、Build Tools、NDK 与 Rust `aarch64-linux-android` target。首次安装 Tauri CLI：

```powershell
cargo install tauri-cli --version 2.11.4 --locked
cargo tauri icon public/icon.svg
```

双击 `启动基金阶梯账本.bat` 会优先运行已构建的独立程序；未构建时会尝试启动 Tauri 原生开发窗口，不会回退打开浏览器。Windows 安装包位于 `src-tauri/target/release/bundle/nsis/`。Android APK 由 `cargo tauri android build --apk --target aarch64 --ci` 生成。

## 使用流程

1. 点击“新增基金”，输入名称、代码和类别。
2. 确认该基金报价最小变动单位（场内基金常用单位为 0.001 元，但应按实际品种规则核实）。
3. 填写上轨、中轨、下轨、昨日收盘价、上一次成交价与当前价格。
4. 选择阶梯基准和方向，观察十档价格与当前价格的位置。
5. 在“交易账本”输入成交价格和份额，系统自动按固定费率估算佣金与其他费用；经手/过户费、印花税按实际发生填写并核对。
6. 在“价格计算”保存价格快照，并定期导出 JSON 备份。

## 费用规则

- 佣金按成交金额的 `0.015%` 估算，其他费用按成交金额的 `0.004%` 估算，均以整数金额核算并四舍五入到小数点后两位（分）。
- 两项费率是全局固定规则，所有基金共用；不为每只 ETF 单独配置费率或最低佣金。经手/过户等费用和印花税按实际发生情况填写。
- 新交易录入价格和数量后，佣金及其他费用会自动估算；可按东方财富实际成交记录修正具体金额。实际保存值按每笔交易单独存档。

## 会计与价格口径

- **涨跌幅**：`(当前价 - 基准价) / 基准价 × 100%`。
- **价格阶梯**：`基准价 × (1 ± n/100)`，`n` 为 1—10；不复利、不以上一档为新基准。
- **买入成本**：成交额 + 买入费用。
- **卖出已实现盈亏**：卖出成交额 − 卖出费用 − 卖出份额对应的加权平均成本。
- **浮动盈亏**：当前参考市值 − 剩余持仓成本；不扣未来卖出费用。
- 成交额和费用均以分为单位做固定点核算；价格用六位小数定点表示。报价价格阶梯按设置的价格最小变动单位舍入。
- 每笔卖出都按成交时间校验当时是否有足够份额；禁止悄悄形成负持仓。

## 已知边界（首版明确不做）

- 不连接东方财富账户、券商 API 或自动交易；公开行情仅在点击刷新时请求。
- 东方财富优先，失败依次回退腾讯、百度股市通；日/周/月 BOLL 历史 K 线同样三级回退（东方财富 → 腾讯 ifzq.gtimg.cn → 百度 finance.pae.baidu.com，不因单一数据源故障丢失 BOLL 功能）。三源均失败时保留原价格，错误信息同时列出三个源的失败原因。行情源可能延迟或不可用，页面显示来源报价时间，不将本机刷新时间冒充行情时间。
- 不进行后台轮询，也不承诺公开行情接口在任何网络环境下都能返回实时数据。
- 不自动读取东方财富交割单；固定费率仅作默认估算，实际费用应按成交记录核对。
- 无云同步、多设备冲突解决、账号系统、云端备份或服务端数据。Windows 与 Android 的本地数据库相互独立，需要 JSON 手动迁移。
- 当前账本的持仓与盈亏是根据用户已录入交易推算的结果；漏记、错记、交易时间错误都会影响结果。
