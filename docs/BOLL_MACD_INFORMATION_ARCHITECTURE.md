# BOLL + MACD 技术状态信息架构设计

> 本文是 BOLL + MACD 技术状态模块的实现约束。实现、测试、文案和界面行为均以本文及配套验收文档为准。若代码与本文冲突，先判断是否存在经用户确认的设计变更；不得以现有实现为理由反向降低要求。

- 状态：批准实施
- 适用范围：基金价格计算页中的 BOLL + MACD 技术状态模块
- 不适用范围：基金账本、交易、持仓、费用、价格阶梯、JSON 备份和行情刷新主流程
- 配套验收：`docs/BOLL_MACD_ACCEPTANCE.md`
- 既有公式依据：`docs/DATA_AND_FORMULAS.md`
- 参数校准依据：`docs/BOLL_MACD_CALIBRATION_REPORT.md`

## 1. 问题定义与目标

现状存在三个结构性问题：

1. 首屏将多个周期、多个指标维度拼接为长句，用户需要自行组合“周期—指标—状态”，信息组织方式与阅读任务不一致。
2. 周期详情存在外层周期折叠与内层“指标依据与历史明细”折叠，日线默认选中仍需二次点击。
3. 当前详情主要是当前快照和少量元数据；MACD 的 DIF、DEA、柱体数值及逐根历史结果未完整呈现，不能称为完整历史明细。

目标阅读顺序固定为：

1. 先知道日、周、月各自处于什么可被数据支持的状态；
2. 再查看该周期 BOLL、MACD 的具体计算依据；
3. 最后在同一详情视图内核对逐根历史计算结果和状态事件。

本次是信息架构和可追溯性改造，不是交易策略优化，也不是指标参数寻优。

## 2. 不可违反的产品边界

- 只描述已确认收盘的日/周/月 K 线；未收盘周期不得参与状态计算。
- BOLL 与 MACD 分别给出有效性，不得用一个总状态掩盖另一指标不可用。
- 日、周、月分别计算、分别描述；不得把跨周期状态合成为买入、卖出、看多、看空或仓位建议。
- “死叉后空头排列”等 MACD 术语只能出现在 MACD 区域，不能归因于 BOLL。
- 不把历史分位解释为未来方向概率，不把描述参数解释为交易阈值。
- 不得用当前快照倒推历史指标，不得伪造历史事件日期，不得用样例值冒充实时计算结果。
- 数据缺失、历史不足、输入无效、来源不可信、指标不可用必须明确区分；不得将未知显示成中性、走平或无事件。
- 技术状态是派生展示数据，不写入基金账本、交易记录或 JSON 备份。
- 不改变行情源优先级、点击刷新机制、账本计算规则和既有 BOLL/MACD 公式口径。

## 3. 信息架构

### 3.1 第一层：市场状态摘要（默认可见）

首屏按周期组织，顺序固定为日线、周线、月线。每个周期一张摘要区域，内容包含：

- 一句简短、自然语言的状态概括；
- BOLL 一行事实依据；
- MACD 一行事实依据；
- 数据状态提示（仅在部分/全部不可用或历史不足时显示具体原因）。

示例仅说明文案结构，不代表实际计算结果：

- 日线：中轨向下，带宽持续收窄。BOLL：中轨向下、带宽持续收窄、确认收盘位于中轨下方。MACD：DIF 位于零轴下方、死叉后空头排列、空头动能减弱。
- 周线：中轨向下，带宽持续扩张。BOLL：中轨向下、带宽持续扩张。MACD：DIF 位于零轴下方（仅展示当前有效字段）。
- 月线：历史不足，暂无法形成完整判断。分别说明 BOLL 与 MACD 的可用性和不足原因。

文案生成规则：

- 只从当前快照的已计算字段生成，不允许在文案层二次推断未提供的状态。
- 先判断指标有效性，再读取状态字段；未知字段必须显示“未知/无法判断”。
- 摘要句只压缩事实，不使用“强势、弱势、反转、机会、风险加大”等带有交易含义的推断词，除非它们是已明确定义且有独立证据的字段。
- 不把“BOLL 有效 3/3、MACD 可用 2/3”作为首屏主句；完整性统计属于数据状态/详情元数据。
- 不再把各周期的带宽、中轨、零轴、交叉拆成四条跨周期长清单。
- 摘要不重复全部数值；数值属于第二层依据。

### 3.2 第二层：指标依据（周期切换一次直达）

周期选择控件固定为日线、周线、月线，默认日线。切换周期后，当前周期的完整详情立即显示。

禁止：
- 周期卡片内再放一个“展开指标依据与历史明细”折叠；
- 外层 `details` 再套内层 `details`；
- 以抽屉、弹窗、额外按钮重新引入同等层级；
- 默认折叠导致用户再次点击才能看到已选周期内容。

详情内容按 BOLL、MACD、数据来源与计算元数据分区。

#### BOLL 依据

有效时展示：

- 公式与参数：BOLL(20,2)、总体标准差口径、当前参数配置版本；
- 当前确认 K 线日期；
- 上轨、中轨、下轨；
- 带宽（BBW）和历史分位；
- 分位实际样本数与窗口长度；
- 带宽阶段及中轨方向；
- 确认收盘在通道中的位置百分比及位置分类；
- 状态确认根数、方向回看窗口、走平容差、近轨距离等影响分类的配置。

无效或历史不足时不展示看似有效的数值；可展示已知的公式配置和具体失败原因。

#### MACD 依据

有效时展示：

- 公式与参数：MACD(12,26,9)；
- 当前确认 K 线日期；
- DIF、DEA、MACD 柱体的真实数值（柱体沿用现有定义 2 × (DIF − DEA)）；
- DIF 零轴位置；
- DIF/DEA 当前排列；
- 柱体动能变化；
- 本根是否产生新金叉/死叉；
- 最近一次已确认金叉/死叉的类型和日期（历史可追溯时）。

“本根新交叉”与“最近一次历史交叉”必须分开。最近交叉缺失或历史范围内不存在时，明确显示“当前加载历史范围内未发现/无法确定”，不得伪造日期。

#### 来源与计算元数据

展示可追溯字段：

- K 线数据源与现价数据源，二者分开；
- 最后确认日期；
- 历史起止日期和确认 K 线数量；
- 是否排除了进行中 K 线；
- MACD EMA 初始化/种子策略、实际输入历史长度（以真实实现为准）；
- BOLL 参数配置版本及实际参数；
- 任何无法从当前管线获得的元数据标为“未提供”，不得猜测。

### 3.3 第三层：历史计算明细（在同一详情内直接呈现）

历史明细位于当前周期指标依据下方，不设置第二次展开入口。

- 数据层保留当前加载范围内的完整逐根历史结果。
- UI 默认展示最近 20 根已确认 K 线；不足 20 根时展示实际可用条数，不补造。
- 可通过分页或日期范围查看更早数据；这是数据量管理，不得再套折叠层。
- 每一行必须携带真实交易日期，并与该行原始确认 K 线一一对应。

BOLL 历史列至少包含：日期、确认收盘、上轨、中轨、下轨、带宽、带宽分位（样本不足则空/未知）、带宽阶段、中轨方向、通道位置。

MACD 历史列至少包含：日期、确认收盘、DIF、DEA、柱体、零轴位置、排列、动能状态、当根交叉事件。

历史事件摘要至少包括（只有计算管线能够可靠计算时才展示）：

- 最近一次金叉/死叉日期和类型；
- 当前 DIF/DEA 排列开始日期；
- 当前带宽阶段开始日期；
- 当前中轨方向开始日期/最近变化日期。

状态起始日期必须按当前算法的状态确认规则逐根回放得出。若状态需要连续 N 根确认，则开始日期定义为“首次满足 N 根确认的当前 K 线日期”，并同时记录该次确认所使用的 N 根观察窗口起点；两者必须分别保存、分别展示，不得简单把回看窗口第一根日期当作状态开始日期。

## 4. 计算数据管线约束

### 4.1 单一历史输入

- 每个周期的 BOLL、MACD 必须使用同一批经过归一化、去重、排序和收盘确认的 K 线。
- 原始已确认 K 线是唯一历史计算依据。
- 指标序列长度、日期键和原始 K 线一一对应；指标预热期可为空值，但不得删除日期行或错位。
- 不允许在 BOLL 与 MACD 的历史计算中使用不同的“当前日期”或混入现价。

### 4.2 逐根计算与批量一致

对任意确认日期 t：

- 使用截至 t 的历史前缀计算出的指标，必须等于完整序列中 t 对应的指标。
- 在历史序列末尾追加未来 K 线，不得改变任何过去确认日期的指标值、交叉事件和状态标签。
- 必须有前缀重放测试和 no-future-bars 测试。
- 批量计算结果必须与逐根前缀重放最终值一致。

### 4.3 MACD EMA 规则

- 沿用现有 MACD(12,26,9) 数学公式和已校准的状态发布历史门槛，不在本任务中调整参数。
- 必须记录实际可用的历史输入长度和现有 EMA 初始化策略；如果当前实现没有可解释的种子元数据，应补充可追溯元数据，但不能改变既有计算结果。
- 历史交叉事件仅在相邻两根确认 K 线之间按 DIF/DEA 穿越关系确认。
- 当前交叉事件和历史交叉列表来自同一次逐根计算，不能由 UI 再次推断。

### 4.4 BOLL 规则

- 沿用 BOLL(20,2)、总体标准差和当前版本化参考配置。
- 每根 K 线按同一配置逐根计算上中下轨、BBW、分位、阶段、中轨方向和位置。
- 分位窗口不足、方向窗口不足、状态确认根数不足时保留未知，不做默认补值。
- 当前配置版本与每个历史结果绑定；不得把新版本参数应用到旧版已存计算结果后仍宣称同版本。

### 4.5 数据源和确认边界

- 保持现有行情源优先级和回退策略。
- 现价源与 K 线源独立记录。
- 无可信交易日期的现价不得合并进已确认技术序列。
- 日线、周线、月线收盘确认严格沿用 `docs/DATA_AND_FORMULAS.md`。
- 历史不足必须报告真实数量、门槛和原因。

## 5. 类型与 API 设计约束

实施时先审查现有类型，尽量向现有模型增量扩展，不重复建立第二套行情模型。

建议新增的序列结构（命名可按仓库风格调整，但语义必须保留）：

- `TechnicalIndicatorHistoryPoint`：date、close、boll、macd；
- `BollHistoryPoint`：upper、middle、lower、bandwidth、percentile、phase、middleDirection、closeLocation；
- `MacdHistoryPoint`：dif、dea、histogram、zeroAxis、arrangement、momentum、crossEvent；
- `TechnicalEventHistory`：最近交叉、当前状态起始日期及其确认元数据；
- `TechnicalCalculationMetadata`：公式版本、配置版本、EMA seed 策略、历史范围、样本数量、来源、确认日期、进行中 K 线排除信息。

以上是语义契约，不要求机械照搬类型名。避免在每根历史点重复存储不变的大块元数据。

## 6. 性能和呈现约束

- 不为展示历史明细重复请求行情；使用当前一次刷新取得的确认 K 线。
- 历史序列仅存放派生内存状态，不写入持久化账本。
- UI 默认只渲染最近 20 根，避免 Android 窄屏和低内存设备一次渲染全部历史。
- 表格支持横向滚动或窄屏适配；不得让页面整体出现横向溢出。
- 历史数据分页/窗口切换不得改变计算结果。
- 不引入无必要的图表库、状态管理库或持久化依赖。
