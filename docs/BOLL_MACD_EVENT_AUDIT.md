# BOLL 触轨后 MACD 交叉事件审计

## 当前实现边界

`src/technical-state/boll-macd-events.ts` 是基于确认收盘 K 线的事件配对层，不是收益回测器，也不发出真实交易指令。

规则固定为：

- 日/周/月周期分别使用各自的确认收盘序列；BOLL 与 MACD 每根都消费同一历史前缀。
- 下轨触发定义为确认收盘价小于或等于当根 BOLL 下轨；之后等待**更晚一根**确认 K 线出现 MACD 金叉。
- 上轨触发定义为确认收盘价大于或等于当根 BOLL 上轨；之后等待**更晚一根**确认 K 线出现 MACD 死叉。
- 触轨当日同时出现交叉，不算“触轨后交叉”，必须等待后续日期。
- 等待期间出现反向 MACD 交叉，或反向 BOLL 触轨，当前 setup 标记为 invalidated。
- 同侧重复触轨不重置首次触发日期；历史结束仍未等到交叉的 setup 保留为 pending。
- 输出触发收盘价、轨道值、确认日期/收盘价、等待 K 线根数、自然日间隔、确认收盘价相对触发收盘价的变化百分比。

## 解释限制

本模块只能识别“收盘价触及/越过轨道”。当前历史输入只保留 close，没有 high/low，因此不能据此声称盘中价格曾触轨。

`closeChangePercent` 是触发日收盘到交叉日收盘的价格变化，不是策略收益；尚未扣除费用、滑点，也未模拟持仓和资金占用。pending / invalidated 不能当作成交。

## 下一步严格回测的前置条件

1. 用真实行情逐只 ETF、逐周期运行事件审计，记录行情源、历史覆盖区间、确认根数和无效/未完成事件。
2. 将交易状态机单独定义并冻结：入场/退出是否必须持仓状态互斥、反向信号如何处理、重复触发如何处理。
3. 冻结资金与成交规则：初始资金、单笔仓位、整手约束、现金不足处理、手续费、最低佣金、滑点、价格精度。
4. 逐笔列出信号日期、下单日期、成交价格、费用、持仓变化、现金、净值；收盘信号只能按约定成交时点执行，不得用当根未来价格。
5. 做滚动样本外验证，并将日/周/月与不同 ETF 分开报告；不能用同一段样本调参再证明该样本有效。

在这些条件完成前，事件审计只能回答“触轨后多久出现交叉、期间价格如何变化”，不能回答策略是否盈利。
