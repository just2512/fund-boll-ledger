# MACD 信号有效性与策略回测契约决策矩阵

> 状态：研究与契约草案；不是生产策略冻结，也不授权修改现有 MACD 输出或价格对比 UI。
> 基线：main `fd2edfe9a715fad8facb7ec15c3b5fdd39b6a334`；真实滚动敏感性 Run `42599861183`，Artifact `13665332001`。

## 1. 先区分三种不同结论

| 层级 | 回答的问题 | 当前可确认事实 | 不得推导 |
|---|---|---|---|
| 数值可计算 | 当前确认序列能否计算 DIF/DEA/柱体 | 现有 MACD(12,26,9) 在至少 35 根确认 K 线上输出；首值作为 EMA seed | 不代表交叉信号稳定 |
| 历史分类稳定性 | 改变历史起点后，分类是否保持一致 | 当前 12 组真实序列中，160 根候选在 1,313 个可比较日期未观察到分类差异 | 不代表未来行情、其他数据源或更长历史必然稳定 |
| 交易信号有效性 | 信号能否形成可执行且样本外有证据的交易规则 | 尚未完成成交、退出、仓位、成本和滚动样本外验证 | 不得输出买卖建议或策略收益结论 |

## 3. MACD 信号状态的候选表达边界（不冻结）

| 状态维度 | 现有字段/事实 | 审计要求 |
|---|---|---|
| 数值 | dif、dea、histogram | 保留原始数值与 seed 日期、barsUsed、preRollBars |
| 零轴 | zeroAxis | 不可替代 DIF/DEA 排列 |
| 线关系 | lineRelation | 表示当前 DIF 与 DEA 的关系，不等同于本根新交叉 |
| 本根事件 | crossEvent | 仅当相邻两根已确认 K 线发生穿越时输出 golden/death |
| 最近历史事件 | lastCross | 表示最近一次历史交叉，不得重复当作本根事件 |
| 排列描述 | arrangement | 需要明确历史交叉未知与当前排列的区别 |
| 动能 | momentum | 单独表达柱体变化，不得代替交叉或零轴状态 |
| 信号有效性 | 当前无独立冻结门槛 | 不允许仅凭 barsUsed >= 35 宣称稳定；也不允许把 160 写成已验证生产阈值 |

未来若引入独立的信号有效性字段，必须同时满足：
1. 与数值计算有效性分离；
2. 明确依据（历史长度、起点敏感性、数据源质量、收盘确认）；
3. 历史快照可复算，且字段语义向后兼容；
4. 对历史不足、来源缺失、冲突日期和未收盘周期给出可诊断状态；
5. 先完成单元测试、真实数据校准和迁移兼容检查，再考虑 UI 消费。

## 5. 事件审计可以回答什么

现有事件审计以确认收盘价触轨（不是盘中 high/low 触轨）为触发条件，要求更晚的确认 K 线出现对应 MACD 交叉。等待期间反向交叉或反向触轨使 setup invalidated；同侧重复触轨不重置首次触发日期；历史结束未确认则 pending。

最新 95 个 confirmed 事件的等待中位数为 13 根、P90 为 22 根、最大 29 根。触发收盘至确认收盘变化范围跨越正负两侧。这些是事件路径描述，不是交易收益，也不能单独决定超时参数。

## 6. 样本外验证的最低设计要求

- 按 ETF、周期分别保留时间顺序；不能随机打散 K 线。
- 每个滚动窗口只用训练区间选择候选参数，验证区间不得参与调参。
- 任何归一化、指标预热、阈值分位和信号配对均只读取 as-of 日期之前可用数据。
- 对每个候选保留完整交易明细：信号日期、下单日期、成交价、费用、滑点、份额、现金、持仓、净值。
- 报告交易次数、持有时间分布、最大资金占用、收益分布、最大回撤及未成交/被拒订单。
- 同时报告不同 ETF、日/周/月周期和不同市场阶段；不能只报告汇总值掩盖分组失效。
- 与简单基准比较，并保留参数选择过程和失败窗口；不能在同一全样本上选参数后再宣称样本外有效。

## 7. UI 解锁条件

以下条件全部取得可复核证据前，现有价格对比模块 UI 保持 `NOT_STARTED`：
- MACD 数值计算与信号有效性语义分离，并完成历史不足状态决策；
- EMA 起点敏感性在更长历史/独立行情来源/更多行情阶段得到复核，或明确限定适用范围；
- BOLL 状态参数经过严格滚动样本外验证并完成正式选择；若没有策略用途，必须明确仅展示描述性状态，不伪装成交易判断；
- 策略交易状态机、成交、资金、成本和滑点契约冻结（若产品范围包含策略回测）；
- 主线单测、生产构建、浏览器 E2E、真实行情逐根验收全部通过；
- 账本实体和 JSON 备份结构保持不变。

本文件只整理证据与决策缺口，不改变生产公式、默认参数、交易行为或 UI。

## 10. MACD 计算可用性状态契约（2026-11-09）

在保留既有 `error` 文本字段兼容性的前提下，`MacdPeriodState.availability` 提供机器可读状态：

| availability | 适用条件 | 数值/交叉字段 | 描述性标签 |
|---|---|---|---|
| `ready` | 输入确认序列有效且达到现有 35 根最低计算要求 | 输出 DIF/DEA/柱体与事件字段 | 按实际计算状态显示 |
| `insufficient-history` | 确认 K 线不足 35 根，或没有已确认收盘历史 | 不输出数值；交叉事件为 `unknown` | 历史不足 |
| `unavailable` | 没有可用历史或缺少可信行情日期，无法判定收盘确认 | 不输出数值；交叉事件为 `unknown` | 数据不可用 |
| `invalid-data` | 日期、价格、重复日期冲突、as-of 或确认序列结构无效 | 不输出数值；交叉事件为 `unknown` | 数据无效 |

约束：
- 35 根仍是既有数值计算下限，不代表信号稳定；本次没有把 160 根候选改成生产门槛。
- `availability` 描述计算输入是否可用，不代表交易信号有效性；后者仍须独立样本外验证。
- `error` 保留具体诊断文本；展示层不得仅凭 `error` 是否存在而把历史不足、来源不可用和数据无效混成同一种状态。
- 所有不可用状态下 `crossEvent` 必须是 `unknown`，不能用 `none` 表示“没有发生交叉”。
- 此状态字段不改变基金账本实体、交易记录和 JSON 备份结构。


## 11. 已明确的触轨配对规则与仍缺失的超时规则

以下规则作为当前策略研究基线，不等于完整交易策略已冻结：

1. 下轨触发：已确认收盘价触及/低于 BOLL 下轨后，等待后续 MACD 金叉。
2. 上轨触发：已确认收盘价触及/高于 BOLL 上轨后，等待后续 MACD 死叉。
3. 同一根 K 线同时触轨和出现预期交叉，不确认；交叉必须发生在触发日期之后。
4. 等待期间出现反向 MACD 交叉或反向 BOLL 触轨，旧 setup 失效。
5. 同侧重复触轨不重置首次触发日期。
6. 若旧 setup 在某根 K 线上失效，而该根又触发新的 setup，则旧 setup 保留 invalidated，新 setup 从该根开始 pending；不得把该根的交叉回填为新 setup 的确认。
7. 历史窗口结束仍未出现确认交叉时，状态保持 pending；不得推断未来确认或成交。
8. 当前定义是“确认收盘价触轨”，不是盘中最高价/最低价曾经穿越轨道。若未来要改为盘中触轨，必须另行定义数据字段和回测口径。

仍未冻结：
- 超时按多少根 K 线计算；日/周/月是否使用同一根数；
- 触发后跨越交易日/停牌/缺失 K 线的计数规则；
- 超时当日若同时出现预期交叉/反向触轨的优先级；
- 确认后何时下单、成交价格、退出、仓位、资金、费用、滑点与复权。

因此当前仅冻结事件配对的基础语义，不能把它称为完整交易策略，也不能据此输出回测收益。
