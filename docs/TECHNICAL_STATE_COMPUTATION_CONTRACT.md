# 技术状态计算共享契约（冻结版）

> 版本：1.0
> 冻结基线：`main` 上本文件与 `src/technical-state/types.ts` 所在提交。
> 范围：BOLL 状态、MACD 状态、组合状态和历史逐根重放的共享输入/输出语义。
> 本契约冻结的是数据形状和时间语义；BOLL 状态判定的阈值必须通过配置显式传入，不允许在各分支内私自选择默认值。

## 1. 不可违反的边界

1. 继续复用 `src/market-data.ts` 的日/周/月行情请求。一次周期 K 线请求供 BOLL 和 MACD 共用；不增加第二套行情请求。
2. 现有 `calculateBollBands` 保留实时现价合并职责。历史状态引擎只接收确认收盘 K 线，不得把盘中现价替换值当成历史收盘。
3. 现有 `calculateMacdPeriod` 是 MACD 计算基线。B 线先审计，再决定以兼容包装器或内部纯函数方式扩展；未经单独证明不得改 MACD 公式或 EMA 初始化。
4. 技术状态是行情派生结果，不进入 `AppData`、基金/交易/快照实体或 JSON 备份。
5. 组合描述层只读取结构化状态，不重新计算指标；未覆盖组合输出 UNKNOWN/中性/分化，不推断买卖指令。

## 2. 共享类型

代码类型以 `src/technical-state/types.ts` 为准：

- `TechnicalInterval`: `daily | weekly | monthly`
- `TechnicalBar`: ISO 交易日期和未舍入的正数收盘价。
- `TechnicalQuoteContext`: 行情源交易日期、源端时间戳（北京时间）和来源。
- `TechnicalHistoryInput`: 某一周期的原始历史 K 线及报价上下文。
- `ConfirmedTechnicalSeries`: 已规范化、升序、日期唯一、仅包含确认收盘 K 线的序列。
- `TechnicalNormalizationResult`: VALID / INSUFFICIENT / INVALID 的显式结果。
- `BollState`: BOLL 数值、带宽变化/分位、中轨方向、收盘位置和有效性。
- `TechnicalStateSnapshot`: 某周期某交易日的 BOLL 状态与现有 MACD 状态。
- `BollStateConfig`: BOLL 窗口、带宽分位窗口、方向窗口、走平容差和连续确认根数均显式提供。

不得用 0、空字符串或任意默认方向表示缺失数据。无效原因必须保留。

## 3. K 线规范化与收盘确认

### 3.1 日期与数值

- 日期格式严格为 `YYYY-MM-DD`，按交易日期升序。
- 收盘价必须是有限正数；不合格行不能参与指标计算，并须在规范化结果中留下可诊断原因。
- 同日期、同收盘价的完全重复记录可折叠为一根。
- 同日期出现不同收盘价属于冲突数据，规范化结果为 INVALID；不得依赖数组先后顺序采用“最后一条覆盖”。
- 周线周期键按周一日期归一化；月线按 `YYYY-MM` 归一化，与现有 `intervalPeriodKey` / `intervalKey` 语义一致。

### 3.2 收盘规则

- 缺少可信源端 `tradingDate` 时，不能确认最新 K 线收盘状态，必须 fail closed。
- 日线：当最新 K 线日期与报价交易日期相同，必须要求源端北京时间日期一致且时间不早于 15:00；时间缺失或日期不一致则排除该根。若最新 K 线日期早于报价交易日，则它是已结束的历史日线。
- 周线/月线：当最新 K 线与报价交易日属于同一周/月时，该根一律视为未收盘并排除；周中 15:00 不能证明周线收盘。报价日期进入下一周/月后，上一周期 K 线才可确认。
- 不使用设备本地时间确认行情收盘。
- BOLL 与 MACD 必须消费同一份 `ConfirmedTechnicalSeries`，不得各自实现一套不同的收盘过滤逻辑。

## 4. BOLL 状态语义

- 固定 BOLL(20,2)，20 根窗口，使用总体标准差（方差除以 20）。
- 上/中/下轨及带宽状态内部保留未舍入数值；显示层再按现有价格精度格式化。
- 带宽百分比：`(upper - lower) / middle * 100`。
- 带宽变化：`(currentBandwidth / priorBandwidth - 1) * 100`；分母无效时返回 INSUFFICIENT/INVALID，不得返回无穷或伪造 0。
- 历史分位使用截至当前日期的尾随窗口，包含当前确认样本；定义为 `count(sample <= current) / sampleCount * 100`。窗口长度和最小有效样本数必须显式配置/记录，不能读取未来样本。
- 中轨方向使用明确的方向窗口；走平容差和连续确认根数由 `BollStateConfig` 提供。状态转换必须基于已确认的连续历史状态，不得只凭一根噪声变化宣称拐头。
- 历史收盘位置：`(close - lower) / (upper - lower) * 100`。该值允许低于 0 或高于 100；边界值必须有测试。
- 实时现价位置（如果 UI 需要）是独立的 live 字段，不得覆盖历史确认快照的 closeLocation。

## 5. MACD 状态语义

- 固定 MACD(12,26,9)：DIF = EMA12 - EMA26；DEA = DIF 的 EMA9；柱体 = 2 × (DIF - DEA)。
- 保持现有 EMA 递推初值规则（首个输入值作为 seed），直到独立的算法变更有基准数据和回归证据。
- 最少 35 根已确认 K 线是现有实现的输出下限，不代表 EMA 已达到数学收敛；输出必须保留预热长度/有效性信息。
- 新金叉/新死叉必须比较相邻两根已确认 K 线；持续 DIF/DEA 排列、零轴位置、最近一次交叉和柱体动能分开表达。
- 一次交叉只能归属于发生交叉的那根确认 K 线；后续日期只能显示持续排列及最近交叉，不得重复生成新事件。
- 历史逐根重放必须从同一条已加载序列的相同起始根开始逐步扩展前缀，确保 EMA seed 一致；不同起点导致的差异应作为预热敏感性测试记录，不得伪称逐根算法错误或静默忽略。

## 6. 历史逐根重放接口语义

- 输入为一个周期的有序原始 K 线及报价上下文；重放器逐根推进。
- 对每个日期 N，只向指标引擎提供截至 N 且已确认收盘的 K 线前缀。
- 输出按 `interval + asOfDate` 唯一标识；保留当日输入边界、确认状态、有效性、BOLL/MACD 结果和来源。
- 必测：追加未来 K 线不改变此前日期结果；全量批量计算与相同起点的逐根前缀计算在共同日期一致；未收盘周期不生成事件；重复/冲突日期处理确定；数据源切换不制造虚假交叉。
- 历史源数据最多 320 根时，只能对实际覆盖范围做历史验证；不得声称验证了未获取的更早时期。

## 7. 配置与未冻结事项

以下参数不可在分支中擅自硬编码，必须由调用方显式提供并记录：

- 带宽分位窗口长度与最小有效样本数。
- 中轨方向观察窗口。
- 走平容差。
- 状态持续/转折确认根数。
- “接近上轨/下轨”的价格距离定义（如状态引擎需要该标签）。

分支可以先实现原始数值和不依赖阈值的状态；需要上述参数的状态在配置未确定前返回 UNKNOWN/INSUFFICIENT。不能为了展示更丰富而自选阈值。

## 8. 并行分支接口责任

| 分支 | 可以修改 | 不得修改 |
|---|---|---|
| `feat/boll-state-engine` | BOLL 纯计算、BOLL 状态及独立测试 | MACD 公式、行情请求、账本类型、UI |
| `feat/macd-state-audit` | MACD 状态审计/兼容适配、MACD 测试 | BOLL 状态算法、行情请求、账本类型、UI |
| `test/technical-history-replay` | 历史重放器、测试夹具、未来数据隔离测试 | 另写指标公式、生产 UI、账本结构 |
| `main` | 共享契约、公共规范化/收盘边界、组合引擎、集成和验收 | 不提前启动 UI |

所有分支从契约冻结后的同一 `main` SHA 创建。短生命周期分支完成定向测试后依次集成，不长期分叉。
