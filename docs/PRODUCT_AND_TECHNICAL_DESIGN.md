# 产品与技术设计方案：原生桌面版与 Android App

## 产品目标

应用仅服务于场内基金手动计算与记账；不管理股票个股，不接入东方财富账户、行情 API、券商 API 或自动交易。

## 功能验收范围

- 价格计算：BOLL 上轨、中轨、下轨、昨日收盘价、上一次成交价五个基准；手动当前价格；各基准独立计算涨跌额和涨跌幅。
- 十档阶梯：上下各 1%—10%，档位按所选基金的报价最小变动单位舍入。当前价标识已越过档位、下一档、未到达或超出范围。
- 交易账本：按时间记录买卖、价格、份额、佣金、经手/过户等费用、印花税、其他费用、备注和费用核对状态。
- 持仓与盈亏：加权平均成本；买入费用计入成本、卖出费用扣减卖出净收入；修改/删除历史交易后全量重算；拒绝超卖。
- 价格历史：手动保存带时间的五个基准和当前价格快照。
- 备份：JSON 全量导入/导出、CSV 交易明细导出。
- 设备：Windows 独立桌面窗口；Android ARM64 APK；两者共用前端代码。

## 技术方案

- React + TypeScript：共享用户界面和计算核心。
- Vite：构建前端资源。
- Tauri 2.11 系列 + Rust：Windows 原生窗口和 Android WebView 容器。日常运行不调用默认浏览器。
- IndexedDB：每台设备分别本地保存数据。首版无云同步；换设备通过 JSON 迁移。
- PWA manifest/Service Worker：仅作为可选浏览器版本，不作为 Windows 主启动方式或 Android App 的交付方式。

## 关键计算规则

相对涨跌幅 = (当前价 - 基准价) / 基准价 × 100%。

价格阶梯以原始基准价计算：
- 上涨 n%：P × (1 + n/100)
- 下跌 n%：P × (1 - n/100)

每档单独舍入到基金档案配置的 tick size，不连续复利。理论档位价格与实际当前涨跌幅分开计算，避免报价舍入造成误导。

买入成本 = 成交金额 + 买入费用。
卖出已实现盈亏 = 卖出成交金额 − 卖出费用 − 本次卖出份额分摊的加权平均成本。
浮动盈亏 = 当前参考市值 − 剩余持仓成本。当前价缺失时显示未提供，不以零价计算。

费用估算仅供录入辅助。佣金费率、最低佣金应按用户实际账户约定填写；经手/过户费用、印花税及其他费用逐笔手动录入，以东方财富实际成交明细核对。不可自动把基金类别转换为固定税费规则。

## Windows 桌面体验

- 默认窗口 1220×850，最小 900×640，可调整大小。
- 双击 BAT 会优先启动已构建的 EXE；未构建时，如果开发工具链齐备则启动 Tauri 独立窗口，不自动打开浏览器。
- 发布版本应使用 NSIS 安装包，在开始菜单/桌面创建快捷方式。
- 安装包需要 WebView2 Runtime；首次本地构建需要 Node.js、Rust、Visual Studio C++ Build Tools 和网络依赖。

## OPPO Find N2 (PUG110) 与 Android 16

- 使用 Tauri Android 工程构建 ARM64 (aarch64) APK。
- Android 16 对应 API 36。Tauri 与 Android 构建工具需要一致配置；当前锁定 Tauri 2.11 系列作为 API 36 基线。
- 外屏、展开内屏、横屏与键盘弹出使用同一套响应式布局；引入动态视口、viewport-fit=cover、安全区域内边距和专门断点。
- 视口自动化测试只能发现部分 CSS 溢出，不代表完成真机兼容验收。需要在 PUG110 真机验证安装、折叠/展开、横竖屏、输入法遮挡、数据持久性、备份恢复。

## 数据风险与边界

- Windows 和 Android 各自有一份 IndexedDB，不会自动同步。
- 用户可清理本地应用数据导致账本丢失；必须定期导出 JSON 到代码目录以外的位置。
- 不把交易数据、密钥或真实账本备份提交到 GitHub。
- 发布 APK 前应添加正式签名配置，但签名密钥不得放入仓库。

## 本地验证命令

    npm install
    npm run test
    npm run build
    npm run desktop:build
    npm run android:init
    npm run android:build

原生构建只能在安装了相应工具链的 Windows/Android 构建环境运行。任何实际设备支持结论都必须以真机测试为依据。
