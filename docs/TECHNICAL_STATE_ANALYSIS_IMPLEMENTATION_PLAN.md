# BOLL + MACD 技术状态分析：并行实施与验收计划

> 状态：计划已确定，尚未代表功能实现或验收通过。
>
> 目标：先交付可复算、可追溯、无未来数据泄漏的计算核心，再改造当前价格对比模块的 UI。不得先做 UI 再反向迁就计算模型。

## 1. 实施原则

1. **源码事实优先**：先审计当前 `main` 的实际实现、调用链、测试和文档；文档规格不能代替源码证据。
2. **契约先行**：并行分支启动前，先在集成主线上确定共享类型、周期日期语义、K 线收盘状态、数据有效性和错误表达。
3. **按边界并行**：BOLL、MACD、历史重放框架可以并行；组合规则必须在两类状态输出明确后集成。
4. **复用而非复制**：沿用现有行情请求、BOLL 计算、MACD 计算和周期收盘规则；不创建第二套行情请求或平行指标实现。
5. **历史逐根验证是硬门槛**：全量历史一次性计算通过，不等于逐根重放通过。
6. **UI 后置**：计算核心和历史验证全部通过后，才启动 UI 改造。
7. **不改变账本边界**：技术状态属于行情分析派生数据，不写入基金、交易、成本、盈亏账本，不改变现有 JSON 备份结构。
8. **失败如实保留**：不删除失败测试、不降低门槛、不用模拟结果冒充真实历史验证，不把 UNKNOWN 或数据不足强行归类。

## 2. 开发拓扑

采用一个集成主线、三个短生命周期并行分支，最后按依赖顺序集成：

| 工作线 | 建议分支名 | 主要职责 | 可并行条件 |
|---|---|---|---|
| 集成主线 | `main` | 源码审计、共享契约、组合规则集成、最终验收 | 始终作为集成基线 |
| A：BOLL 状态 | `feat/boll-state-engine` | 带宽、历史分位、中轨方向/拐头、价格区间位置、状态转换 | 共享契约冻结后 |
| B：MACD 状态 | `feat/macd-state-audit` | 审计并复用现有 MACD，实现缺失状态字段及确定性事件输出 | 共享契约冻结后 |
| C：历史重放 | `test/technical-history-replay` | 逐根推进框架、未来数据隔离、周期收盘测试、结果对照工具 | 重放输入/输出契约冻结后 |

分支是短期隔离工具，不是长期维护的产品分叉。每条分支完成定向测试后尽快集成；避免所有分支开发完毕后一次性大合并。是否使用 PR 由仓库现行协作习惯决定，不把 PR 流程本身变成额外阻塞。

### 分支边界

- A 只负责 BOLL 状态及其测试，不改 MACD。
- B 只负责 MACD 状态及其测试；先确认现有 `src/macd.ts`、测试及调用链，禁止无理由重写已有 MACD 算法。
- C 负责历史重放和测试基础设施，不另写一套简化 BOLL/MACD 公式。最终必须调用正式计算引擎。
- 组合引擎只在集成主线实现，避免 A/B 对组合语义各自作出假设。
- UI 不加入 A/B/C；计算验收通过后另行开工。

## 3. 第一步：源码审计与契约冻结

在创建并行分支前完成：

- [ ] 审计现有 BOLL 公式、数据输入、历史长度、异常处理及调用链。
- [ ] 审计现有 MACD(12,26,9) 公式、EMA 初始化/预热、交叉判定、柱体动能和测试。
- [ ] 审计日/周/月 K 线日期归一化与收盘确认逻辑。
- [ ] 审计行情源切换时的 K 线一致性、重复/缺失日期处理。
- [ ] 区分“源码已实现”“只有文档规格”“部分实现”“缺失”“相互冲突”。
- [ ] 确定共享类型和边界测试样本。

### 共享契约必须表达的内容

具体类型以源码审计结果为准，至少需要统一以下语义：

| 契约维度 | 必须明确的内容 |
|---|---|
| 周期 | 日、周、月独立计算，不跨周期混用 |
| 日期 | 交易日期及周/月周期键的规范化方式 |
| K 线状态 | 已收盘、未收盘、缺失、异常 |
| 数据来源 | 来源标识、切源情况、数据有效性 |
| BOLL 结果 | 轨道值、带宽、分位、方向、价格位置及有效样本范围 |
| MACD 结果 | DIF、DEA、柱体、排列、零轴、最近交叉、本根新事件 |
| 结果有效性 | VALID、INSUFFICIENT、INVALID，不能用空值或零值伪装未知 |
| 时间边界 | 每个历史时点只能读取当时已可获得的数据 |

契约冻结不代表所有阈值都已最终确定。对尚无证据支持的阈值，应作为明确配置或待验证项记录，不能为了让分支开工而随意定值。

## 4. 第二步：三路并行开发

### A 线：BOLL 状态引擎

- [ ] 复用现有 BOLL(20,2) 轨道计算，不重复请求行情。
- [ ] 计算带宽及近 1/3/5 根变化。
- [ ] 计算历史分位；每个日期的分位只能使用该日期及之前的数据。
- [ ] 识别收窄、持续收窄、扩张、持续扩张及收窄/扩张转折。
- [ ] 识别中轨方向和拐头，明确连续观察窗口及走平边界。
- [ ] 计算价格相对上下轨及中轨的位置。
- [ ] 对历史不足、轨道无效、分母为零和异常价格输出明确无效状态。
- [ ] 为边界值、窗口长度、缺失数据和状态转换编写单元测试。

### B 线：MACD 状态审计与补齐

- [ ] 先确认现有 `src/macd.ts` 及测试的真实行为。
- [ ] 沿用 MACD(12,26,9) 公式及既有初始化规则；任何调整必须有独立依据和回归测试。
- [ ] 将新金叉/新死叉与持续 DIF/DEA 排列分离。
- [ ] 明确 DIF、DEA 相对零轴的位置。
- [ ] 明确柱体增强、减弱、方向转换的计算定义。
- [ ] 只对已确认收盘的 K 线生成正式交叉事件。
- [ ] 保留现有周/月线周期结束确认规则；周中 15:00 不构成周线收盘证明。
- [ ] 检查历史预热不足、重复事件、数据源切换及日期错位。
- [ ] 对已有 MACD UI 所依赖的字段保持兼容，必要的变更通过明确适配层完成。

### C 线：历史逐根重放框架

- [ ] 建立确定性的历史 K 线输入夹具和日期推进器。
- [ ] 每次推进只向计算引擎提供截至当前日期可见的数据。
- [ ] 保存每个日期的输入边界、收盘状态、计算结果和有效性。
- [ ] 建立未来数据隔离测试：追加未来 K 线不得改变过去日期的结果。
- [ ] 建立全量计算与逐根重放的共同日期对照。
- [ ] 建立周期收盘测试：未结束周/月线不得提前进入正式状态。
- [ ] 建立数据源切换、缺失日期、重复日期和异常 K 线测试。
- [ ] 对 EMA 预热长度及计算起点敏感性进行单独验证，区分正常初始化差异与算法错误。
- [ ] 重放框架必须调用 A/B 最终集成的正式计算函数，不能用测试专用简化公式替代。

## 5. 第三步：集成与组合状态

A/B/C 完成定向测试后，按依赖顺序集成：

1. 合入共享契约及类型。
2. 合入 BOLL 状态引擎，运行 BOLL 定向测试。
3. 合入 MACD 状态输出，运行 MACD 及原有回归测试。
4. 接入历史逐根重放，运行逐日期对照。
5. 在集成主线实现组合规则和描述生成。

组合规则要求：

- 输入只来自 BOLL/MACD 结构化状态，不在描述层重复计算指标。
- 交叉事件与持续排列必须分别表达。
- 日、周、月各自输出，禁止把一个周期的交叉事件挪用到另一个周期。
- 周/月未收盘时只能展示明确标记的背景信息，不得冒充已确认状态。
- BOLL 与 MACD 分化时如实显示分化，不强行合成单向结论。
- 未覆盖的状态组合返回中性或 UNKNOWN，不得猜测。
- 每条文字描述必须能追溯到具体状态字段和触发条件。
- 不生成买入、卖出或收益保证类结论。

## 6. 计算核心验收门槛

以下门槛全部通过，才允许启动 UI：

| 验收范围 | PASS 条件 |
|---|---|
| BOLL 公式 | 与项目约定公式一致，边界及无效输入有测试 |
| MACD 公式 | 与审计确认的公式、初始化及预热规则一致 |
| 状态确定性 | 相同输入、相同配置得到相同输出 |
| 逐根重放 | 历史每个日期仅使用当日及以前可见数据 |
| 未来数据隔离 | 添加未来数据不改变此前日期状态 |
| 结果对照 | 全量历史计算与逐根重放在共同日期一致；初始化差异有明确解释和边界 |
| 交叉事件 | 只在实际交叉的确认收盘 K 线上生成一次 |
| 周期收盘 | 未结束周/月 K 线不生成正式周/月事件 |
| 历史分位 | 不读取未来样本 |
| 数据源切换 | 不因切源、缺失或重复 K 线产生虚假交叉或错误状态 |
| 数据不足 | 明确输出 INSUFFICIENT，不强制分类 |
| 组合描述 | 每条描述可追溯至结构化条件 |
| 账本隔离 | 不改变 Fund/Trade/Snapshot 等账本数据及 JSON 备份契约 |
| 原有回归 | 现有测试和构建不因新功能退化 |

失败测试必须保留并修复真实根因，不得删除测试或降低断言来获得绿色结果。

## 7. CI 与集成效率

- 分支开发期间优先运行定向单测、类型检查和必要的构建检查。
- 不因每次小幅提交都重复触发完整 CI；但合并前必须运行完整相关检查。
- 如果 self-hosted runner 排队，记录真实排队和执行状态，不把排队当成测试通过。
- 各分支共享同一组脱敏历史测试夹具，分别维护自己的断言，避免重复造数。
- 每次集成后立即检查冲突、运行受影响测试，再继续合入下一分支。
- 不以“分支已合并”代替功能验收。

## 8. 第四步：UI（计算核心通过后才启动）

UI 在现有“当前价格对比”模块内升级，不再堆叠多个平行指标面板：

1. 顶部显示一条综合技术状态描述。
2. 中间并列展示 BOLL 与 MACD 两张状态卡；窄屏改为纵向排列。
3. 默认折叠详细计算依据；展开后显示轨道/带宽/分位/中轨变化，以及 DIF/DEA/柱体/交叉日期。
4. 周线、月线作为背景信息独立展示，明确标记已收盘或未收盘。
5. 历史状态作为独立折叠区域，按交易日期查看当日状态及计算依据。
6. 保留现有 MACD 多空判断所承担的信息，不重复展示同一字段；兼容现有面板收起/展开和本地状态保存。
7. 状态颜色不能成为唯一表达方式，始终保留文字标签。
8. 不把技术分析派生结果写入交易账本或 JSON 备份。

UI 验收至少覆盖桌面、Android 窄屏、OPPO Find N2 外屏和展开内屏；响应式布局可以变化，但状态语义和计算结果必须一致。

## 9. 执行状态记录

每个任务只允许使用以下状态：

- `NOT_STARTED`：尚未开始。
- `IN_PROGRESS`：正在实施。
- `PASS`：有测试日志或可复核证据证明通过。
- `FAIL`：有明确失败证据，需修复。
- `BLOCKED`：存在外部依赖或环境阻塞，并记录阻塞原因。
- `UNKNOWN`：尚无足够证据，不得推定通过。

当前计划文件的提交只表示实施方案已入库，不代表任何计算功能、历史验证或 UI 已经完成。
