# 验收与测试计划

## 1. 自动化测试

前端与核心公式：

    npm run test
    npm run build

Windows 原生：

    npm run desktop:build

Android ARM64：

    npm run android:init
    npm run android:build

GitHub Actions 的 Native App Build 是手动触发，构建包会以 artifact 形式保留 14 天。工作流成功仍不能替代实体设备验收。

## 2. 价格计算验收

1. 新建基金 A，tick size 为 0.001。
2. 输入上轨 10.800、中轨 10.000、下轨 9.200、昨收 10.500、上一次成交价 10.500、当前价 10.950。
3. 当前价格相对上轨约 +1.39%；相对中轨 +9.50%；相对昨收及上一次成交价 +4.29%。
4. 以 10.500 为基准，涨 1% 的未舍入值为 10.605，跌 1% 为 10.395。
5. 将 tick size 改成 0.01，验证对应价格档位按 0.01 舍入。
6. 当前价超过 +10% 或低于 -10% 时显示超出十档范围，不能把它错误标成第十档。
7. 清空当前价或基准价时，百分比和档位状态进入待输入状态，不显示 NaN 或虚假的 0%。
8. 上轨 12、下轨 8、当前价 10 时日 BOLL 区间位置为 50% 且不变色；日位置 ≥100% 仅数值红色、≤0% 仅数值绿色。周/月位置 ≥50% 整个模块红色、<50% 整个模块绿色；周/月轨道价不得显示成价格输入；无效轨道需显示待输入。
9. 为至少两只 ETF 分别设置不同的阶梯基准和方向，切换基金及重启应用后确认各自选择保持独立。

## 3. 交易、成本和费用

1. 买入 100 份 @ 10.00，佣金 1.00 元；再买入 100 份 @ 12.00，佣金 1.00 元。总成本应为 2202.00 元、持仓 200 份。
2. 卖出 100 份 @ 13.00，佣金 1.00 元。成本分摊应为 1101.00 元，已实现盈亏应为 198.00 元，剩余成本 1101.00 元。
3. 尝试在最早时点卖出超过当时持仓份额，保存必须被拒绝。
4. 编辑、删除一笔交易后，检查后续持仓、成本和已实现盈亏重算。
5. 至少建立两只基金，在全部基金视图按基金、日期区间、买卖方向和关键词筛选；核对筛选结果与费用汇总。
6. 从跨基金列表编辑、删除非当前选中基金的交易，确认基金归属不变、另一基金账本不受影响；保存后分别检查两只基金持仓。
7. 拆分填写佣金、经手/过户等费用、印花税、其他费用，核对费用合计与买入现金支出/卖出净收入。
8. “估算佣金”只能用于辅助填写；需逐笔对照东方财富交割单。已核对状态必须由用户手动勾选。
9. 删除基金时，关联交易和快照应按提示一并删除，并要求二次确认。

## 4. 备份与历史

1. 输入至少两只基金、多笔交易、两条价格快照。
2. 导出 JSON 与 CSV；CSV 用 Excel 打开核对中文编码及字段。
3. 导入结构非法 JSON、重复 ID、无效枚举/日期/价格/费用、孤立基金引用或超卖记录时，必须显示具体校验原因且当前账本不变。
4. 同一基金连续保存至少两条快照，历史页按创建时间比较上一条同基金快照，分别核对上轨、中轨、下轨、昨收、上次成交价的绝对变化和涨跌幅；不同基金不得交叉比较。缺少任一价格或上一基准为零时应明确显示不可计算。
5. 导入合法 JSON 前提示会替换当前设备数据，并要求确认。
6. 用 JSON 恢复后核对基金、交易明细、持仓和快照完整；旧备份中的基金级佣金配置应被清理，历史交易费用原值应保留。
7. 刷新页面或关闭并重新启动原生应用，确认本地数据仍在。
8. 用 IndexedDB v1 账本升级到 v2，确认旧 app-state 主记录中的基金、交易、快照不变，仅新增元数据 store，并记录 fromVersion=1、toVersion=2。
9. 有数据但从未发起 JSON 导出时显示提醒；未满 7 天不提醒、满 7 天提醒；发起完整 JSON 导出后将时间写入元数据，重启后提醒状态保持解除。提醒记录的是导出动作，不代表文件已另存到其他安全位置。

## 6. OPPO Find N2 (PUG110) 与 Android 16

自动化视口测试包括 360×780 外屏、720×900 展开屏、844×390 横屏、1280×900 桌面视口。它们是 CSS 回归检查，不能视为真机结果。

在实际 PUG110 安装 APK 后逐项验收：

- [ ] APK 可安装、启动、退出和再次启动。
- [ ] 折叠、展开、旋转后价格输入与阶梯可用，无页面级横向溢出。
- [ ] 软件键盘弹出时当前输入框与保存按钮仍可访问，弹窗可上下滚动。
- [ ] 五基准与当前价输入后实时重算；十档标记正确。
- [ ] 新建基金、买入、卖出、费用和盈亏保存后强制结束并重启，数据仍在。
- [ ] JSON 导出与恢复完整；恢复前有覆盖确认。
- [ ] 行情不自动轮询；仅点击刷新时请求东方财富，验证失败时百度兜底。
- [ ] 校验行情代码、当前价、昨收和报价时间；异常时不覆盖当前价格。
- [ ] 手动刷新计算日 BOLL 并分别获取周/月区间位置所需数据；日 BOLL 轨道四舍五入固定到小数点后三位；周/月轨道价不显示，只用来计算随当前价实时变化的区间位置。
- [ ] 刷新写入的五个价格仍可手动修改；日线失败时现价/昨收更新，原 BOLL 数值保留并显示提示。
- [ ] 双源失败保留原价格并显示错误，成功时显示报价来源、源端时间和日涨跌幅。

兼容性只有在生成真实 APK 并于目标设备完成验证后，才能标记 PASS。

## 7. 缺陷记录

每个问题记录：重现步骤、预期、实际表现、设备/系统/WebView 版本、日志或截图、测试数据（请用虚构数据）。修复后增加自动化回归，不把真实投资账本上传到 issue 或代码仓库。

## 8. Windows / Android 版本升级

1. 执行 `npm run verify:upgrade-contract`，要求 package.json、package-lock、Cargo.toml、Cargo.lock、tauri.conf.json 版本一致，Windows identifier/productName/currentUser 不变，IndexedDB DB/store 名不变。
2. Windows 旧版本安装后创建基金、交易和快照；安装新 NSIS 包覆盖升级（不先卸载），确认账本数据仍在。
3. Android 安装旧版本并录入数据；用相同 applicationId、相同签名证书且更高 versionCode 的新 APK 执行 `adb install -r`，确认基金、交易、快照仍在。
4. 使用不同签名证书的 APK 必须拒绝作为升级包；不得通过卸载重装掩盖签名不匹配。
5. 旧临时签名 APK 切换到长期签名 APK 前，必须先导出完整 JSON，再进行一次性迁移安装并恢复数据。
## 6. BOLL + MACD 技术状态

1. BOLL(20,2) 轨道与既有价格计算保持一致；校验 BBW 公式、历史分位窗口、最少样本门槛、带宽阶段、中轨方向和确认收盘位置。
2. 日/周/月分别使用显式 BOLL 参考配置；未配置时输出 UNKNOWN，不在 UI 层临时补阈值。
3. MACD(12,26,9) 校验 EMA 初始化、DIF/DEA/HIST、交叉事件、持续排列、DIF 零轴和柱体动能方向。
4. MACD 产品状态发布门槛：日线 160 根、周线 160 根、月线 100 根已确认 K 线；不足时不发布稳定状态。35 根仅是公式计算下限。
5. 日/周/月分别输出 BOLL + MACD 描述；周线/月线未确认 K 线不得参与；周期新交叉与持续排列必须分离。
6. 对每个历史 as-of 逐根重放，只能读取该日期之前的确认 K 线；逐根结果与批量计算结果一致，追加未来 K 线不得改变既有结果。
7. 在现有价格对比模块验证首屏摘要、折叠详情和窄屏视口；不新增独立页面，不修改 Fund/Trade/Snapshot 数据结构。
8. 真实行情验收覆盖 4 只 ETF × 日/周/月；记录数据源、历史覆盖、确认根数、敏感性结果和失败原因。数据源故障不得通过跳过标的或更换未授权来源掩盖。
9. 不验收策略回测、订单、成交、资金、费用、滑点、收益或买卖指令；这些不属于技术状态分析交付范围。
