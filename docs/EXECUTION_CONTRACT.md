# 执行契约（强制）

本文件是 `fund-boll-ledger` 当前 BOLL + MACD 技术状态分析工作的长期执行约束。新会话、上下文压缩或中断恢复时，必须重新读取本文件、需求台账和实施计划，不得依赖聊天记忆。

## 1. 唯一产品范围

当前唯一目标：在现有基金价格对比模块中，正确展示已确认日/周/月 K 线上的 BOLL 与 MACD 技术状态及其客观描述。

实施顺序固定为：

1. 审计现有源码、调用链、数据来源和周期确认规则。
2. 复核并完善 BOLL 状态计算。
3. 复核并完善 MACD 状态计算。
4. 组合 BOLL 与 MACD 的描述性结果，不生成交易方向。
5. 完成历史逐根重放和未来数据隔离验证。
6. 在现有价格对比模块内完成展示，不新增独立产品模块。
7. 完成 Windows/Android 相关回归和 CI 验收。

需求和顺序以 [技术状态分析实施计划](TECHNICAL_STATE_ANALYSIS_IMPLEMENTATION_PLAN.md) 中最新的范围校正章节为准；逐项状态以 [技术状态需求验收台账](TECHNICAL_STATE_REQUIREMENTS.json) 为准。

## 2. 明确禁止的范围

本项目不是回测工程。当前授权范围**不包含**：

- 策略回测、收益率、胜率、回撤、最大资金占用或交易绩效报告。
- 买卖信号、交易建议、自动交易、订单、委托、成交、持仓模拟。
- 策略资金分配、手续费、最低佣金、滑点、交易单位或公司行为模拟。
- 新增 `src/backtest/`、独立回测页面、策略工作台、策略结果 UI 或回测数据工作流。
- 修改 Fund/Trade/Snapshot 账本结构、既有交易记录语义或 JSON 备份契约。
- 后台轮询、账户连接、云同步或策略推送。

已有 `src/technical-state/boll-macd-events.ts` 是既存事件研究辅助代码，不是本次产品交付范围；不得将它接入买卖流程、UI 或回测模块，也不得以它替代本次技术状态验收。

未经用户明确授权，不得把“BOLL 触轨后等待 MACD 金叉/死叉”改造成交易策略或订单执行逻辑。

## 3. 修改边界

- 先审计并复用现有 BOLL、MACD、行情请求、确认 K 线和历史重放实现；禁止平行重写。
- 每项代码修改必须关联本台账中的需求 ID，并说明其必要性。
- 不增加用户未要求的功能、页面、数据字段、存储结构、依赖或外部服务。
- 不删除、合并、降级原始需求；发现范围外问题只记录，不实施。
- 不做无关格式化、目录搬迁或顺手优化。
- 如果需求冲突、数据契约变化、安全风险或不可逆风险出现，停止受影响的修改；普通 CI 失败继续定位修复。

## 4. 数据和计算硬约束

1. BOLL 与 MACD 只能使用已确认收盘 K 线。
2. 日/周/月周期分别确认；未收盘周线/月线不得进入状态计算。
3. 历史重放每个 as-of 只能使用当时可见的 K 线，禁止未来数据泄漏。
4. 指标状态、最近交叉事件和持续排列必须分开表达。
5. BOLL 状态阈值必须显式配置并有数据依据；未配置时输出 UNKNOWN，不得自行补默认阈值。
6. MACD 柱体动能必须同时考虑正负方向和绝对值变化，不得把数值上升直接等同于动能增强。
7. 组合描述只陈述指标事实、周期和数据状态，不推导买卖方向或交易指令。

## 5. 状态与证据规则

状态只允许使用：

- `NOT_STARTED`
- `IN_PROGRESS`
- `PASS`
- `FAIL`
- `BLOCKED`
- `MISSING`
- `UNKNOWN`

规则：

1. 只有实际代码、对应测试、相关 CI 和可追溯证据全部满足，才能标记 `PASS`。
2. 文档、类型定义、空函数或未接入生产调用链的代码，不构成功能完成。
3. 测试文件存在不等于测试通过；单测通过不等于真实行情验收通过。
4. `PASS` 必须附提交 SHA 和真实 CI/验收记录；没有证据不得猜测。
5. 数据源 HTTP 失败、超时或数据不完整必须保留为 BLOCKED/FAIL，不得改成 skip 或降低断言。
6. 不得把单标的成功描述成多标的成功，也不得把局部步骤通过描述成整个工作流通过。
7. 不得删除未完成项或修改验收条件来制造全部完成。

## 6. 恢复执行固定流程

每次恢复工作必须：

1. 读取本文件、需求台账、实施计划、\`docs/TECHNICAL_STATE_SOURCE_AUDIT.md\` 和相关测试计划。
2. 获取当前目标分支、HEAD SHA、工作区状态和最近提交。
3. 核对相关 CI 的 run、job、step 和日志；排队/运行中不算通过。
4. 将台账状态与当前代码和 CI 重新核对；发现历史状态过期先修正。
5. 从当前顺序中第一个未完成且依赖已满足的事项继续。
6. 修改后运行定向测试；阶段验收还要运行类型检查、生产构建、E2E 和所需真实行情验收。
7. 更新台账并附证据；最终检查 diff，确认没有越界文件和行为。

## 7. 完成声明

只有所有必需需求均为 `PASS`，且没有未解决的 `FAIL`、`BLOCKED`、`MISSING` 或 `UNKNOWN`，才能声明当前技术状态分析范围全部完成。

**执行契约、需求台账或 CI 检查本身通过，不代表 BOLL + MACD 功能已经全部完成。**
